# 쉼표 — 프로토타입 + 로그인 백엔드 + 신고/필터 + 5개 게시판 (이메일/카카오/구글)

디시인사이드 스타일 레이아웃에 힐링 톤을 입힌 커뮤니티 프로토타입에, 이메일/비밀번호 로그인과 카카오·구글 소셜 로그인, 운영정책 문서(`힐링사이트_운영정책.md`)에 따른 금칙어 필터·신고·운영자 검수 기능, 그리고 처음 제안하셨던 5개 게시판 전부가 실제로 동작하는 버전이에요.

## 실행 방법

컴퓨터에 Node.js가 설치되어 있어야 해요 (https://nodejs.org 에서 LTS 버전 설치).

1. 이 폴더를 원하는 위치에 압축 해제
2. 터미널에서 이 폴더로 이동
3. 아래 명령어 실행

```
npm install
npm start
```

4. 브라우저에서 http://localhost:3000 접속

이메일/비밀번호 회원가입·로그인은 별도 설정 없이 바로 동작해요. 카카오/구글 로그인은 아래 "소셜 로그인 설정하기"를 따라 API 키를 먼저 발급받아야 동작해요. (키가 없어도 사이트 자체는 정상적으로 열려요 — 카카오·구글 버튼을 누르면 설정이 필요하다는 안내 화면이 떠요.)

> ⚠️ **주의: `public/index.html` 파일을 더블클릭하거나 미리보기 창으로 직접 열면 안 돼요.**
> 이 사이트는 게시판 목록·글·댓글을 서버(`npm start`)에서 실시간으로 받아와요. 파일을 서버 없이 직접 열면(또는 다른 프로그램의 파일 미리보기 안에서 열면) 이 데이터를 받아올 수 없어서 게시판이 안 보이거나, 브라우저 콘솔에 `SecurityError: ... about:srcdoc` 같은 에러가 뜰 수 있어요. 반드시 위 1~4번처럼 `npm install` → `npm start` 실행 후 브라우저 주소창에 `http://localhost:3000` 을 직접 입력해서 접속해주세요.

## 소셜 로그인 설정하기

### 1. `.env` 파일 만들기

프로젝트 폴더의 `.env.example` 파일을 복사해서 `.env`라는 이름으로 저장하세요. 이 파일에 발급받은 키를 채워 넣을 거예요.

### 2. 카카오 로그인 키 발급받기

1. https://developers.kakao.com 접속 → 카카오 계정으로 로그인
2. "내 애플리케이션" → "애플리케이션 추가하기" → 앱 이름(예: 쉼표) 입력 후 생성
3. 생성된 앱 클릭 → 좌측 메뉴 "앱 키"에서 **REST API 키** 복사 → `.env`의 `KAKAO_CLIENT_ID`에 붙여넣기
4. 좌측 메뉴 "카카오 로그인" → 활성화 설정을 ON으로 변경
5. 같은 화면의 "Redirect URI"에 `http://localhost:3000/auth/kakao/callback` 추가 후 저장 (배포하면 실제 도메인 주소로 하나 더 추가해야 해요)
6. 좌측 메뉴 "카카오 로그인" → "동의항목"에서 닉네임, 이메일을 "필수 동의" 또는 "선택 동의"로 설정 (이메일은 카카오 비즈니스 채널 심사가 필요할 수 있어요 — 심사 전에는 이메일 없이 닉네임만 받아와요)

### 3. 구글 로그인 키 발급받기

1. https://console.cloud.google.com 접속 → 구글 계정으로 로그인
2. 새 프로젝트 생성 (또는 기존 프로젝트 선택)
3. 좌측 메뉴 "API 및 서비스" → "OAuth 동의 화면" → User Type "외부" 선택 → 앱 이름, 이메일 등 기본 정보 입력 후 저장 (테스트 단계에서는 "테스트 사용자"에 본인 구글 계정을 추가해두면 바로 로그인해볼 수 있어요)
4. 좌측 메뉴 "사용자 인증 정보" → "사용자 인증 정보 만들기" → "OAuth 클라이언트 ID" → 애플리케이션 유형 "웹 애플리케이션" 선택
5. "승인된 리디렉션 URI"에 `http://localhost:3000/auth/google/callback` 추가 후 만들기
6. 발급된 **클라이언트 ID**, **클라이언트 보안 비밀번호**를 각각 `.env`의 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`에 붙여넣기

### 4. 서버 재시작

`.env`를 채운 뒤 `npm start`로 서버를 다시 시작하면 로그인 화면의 "카카오로 3초 만에 시작하기" / "구글로 로그인" 버튼이 실제로 동작해요.

## 이메일 인증 · 비밀번호 찾기 메일 보내기 설정하기

이메일 인증 메일과 비밀번호 재설정 메일은 Gmail 계정으로 발송해요.

1. Gmail 계정에서 [구글 계정 관리 > 보안](https://myaccount.google.com/security) → "2단계 인증"을 켜주세요.
2. 2단계 인증을 켠 뒤 같은 화면에서 "앱 비밀번호"를 검색해 들어가서, 새 앱 비밀번호를 발급받으세요. (일반 로그인 비밀번호와는 달라요.)
3. `.env`에 아래처럼 채워주세요.
   ```
   GMAIL_USER=본인의gmail주소@gmail.com
   GMAIL_APP_PASSWORD=발급받은16자리앱비밀번호
   ```
4. 서버를 재시작하면 실제로 메일이 발송돼요.

`GMAIL_USER`/`GMAIL_APP_PASSWORD`를 채우지 않아도 사이트는 정상 동작해요 — 실제 메일을 보내는 대신 서버 콘솔에 인증/재설정 링크를 그대로 출력해줘서, 개발 중에는 그 링크를 복사해서 테스트할 수 있어요.

## 이미지 업로드(Cloudinary) 설정하기

글쓰기 사진 첨부, 프로필 사진은 [Cloudinary](https://cloudinary.com)라는 무료 이미지 저장 서비스에 올라가요.

1. [cloudinary.com](https://cloudinary.com)에서 무료로 가입해요.
2. 로그인 후 [대시보드(console.cloudinary.com)](https://console.cloudinary.com) 왼쪽 메뉴에서 "API Keys"를 클릭해요.
3. 목록에 있는 값 중 **"Root"라고 표시된 키**의 Cloud Name, API Key, API Secret 세 가지를 복사해요. (처음 만든 키가 아니라 Root 키를 써야 해요 — 새로 만든 키는 기본적으로 업로드 권한이 없을 수 있어요.)
4. `.env`에 아래처럼 채워주세요.
   ```
   CLOUDINARY_CLOUD_NAME=대시보드에서_확인한_Cloud_Name
   CLOUDINARY_API_KEY=Root_키의_API_Key
   CLOUDINARY_API_SECRET=Root_키의_API_Secret
   ```
5. 서버를 재시작하면 이미지 업로드가 동작해요.

세 값을 채우지 않으면 사이트는 정상 동작하지만, 이미지 업로드 시도 시 "이미지 업로드가 아직 설정되지 않았어요"라는 안내가 떠요.

## 게시판 추가·수정하기 (코드 수정 없이, 운영자 화면에서)

이제 게시판은 코드가 아니라 `data/boards.json`에 저장돼요. `ADMIN_EMAILS`에 등록된 계정으로 로그인해서 "운영자" 메뉴 → "운영자 · 게시판 관리"에서 직접 할 수 있어요.

- **새 게시판 만들기**: 이름, 카테고리(감정 · 마음 / 감각 · 속도 늦추기 / 연결 · 온기), 홈 화면에 보일 태그·짧은 설명을 입력하고 "게시판 만들기"를 누르면 바로 만들어져요. 이름 입력칸에 자동완성으로 아이디어 문서에 있던 후보들(익명 고민방, 필사 게시판, 감사일기 등)이 떠요.
- **이름 변경**: 각 게시판의 "수정" 버튼으로 이름·카테고리·태그·설명을 바꿀 수 있어요.
- **숨김/표시**: "숨기기"를 누르면 홈 화면·카테고리 탭·사이드바에서 바로 사라져요 (글 목록 조회·글쓰기도 막힘). 기존 글은 사라지지 않고, "표시하기"를 누르면 다시 열려요.
- **순서 바꾸기**: ▲▼ 버튼으로 같은 카테고리 안에서 순서를 바꿀 수 있어요.
- **삭제**: 게시글이 하나도 없는 게시판만 완전히 삭제할 수 있어요. 게시글이 있으면 삭제 대신 숨김 처리를 하도록 안내해요.

새로고침 없이도 홈 화면·카테고리 탭·사이드바·글쓰기 화면의 게시판 선택 목록이 즉시 반영돼요. (`GET /api/boards`가 공개용 게시판 목록, `GET /api/admin/boards`가 숨김 게시판까지 포함한 운영자용 전체 목록이에요.)

## 운영자 화면 설정하기 (신고 관리 / 게시판 관리)

`.env`의 `ADMIN_EMAILS`에 본인 이메일을 넣으면, 그 이메일로 회원가입/로그인했을 때 상단 메뉴에 "운영자" 링크가 생겨요.

```
ADMIN_EMAILS=cho님의이메일@example.com
```

여러 명이 운영자면 콤마로 구분해서 넣으면 돼요 (`ADMIN_EMAILS=me@example.com,partner@example.com`). `.env`를 수정한 뒤에는 서버를 재시작해야 반영돼요.

## 무엇이 실제로 동작하나요

- 이메일/비밀번호 회원가입·로그인·로그아웃 (비밀번호는 bcrypt로 암호화)
- 카카오/구글 로그인: 버튼 클릭 → 해당 서비스 로그인/동의 화면 → 자동으로 계정 생성 후 로그인
- 같은 이메일로 이미 이메일 가입한 계정이 있다면, 소셜 로그인을 해도 새 계정을 만들지 않고 기존 계정에 연결돼요 (계정 하나로 이메일 로그인과 소셜 로그인을 모두 쓸 수 있음)
- 로그인 안 하고 "글쓰기"를 누르면 로그인 화면으로 이동, 로그인/가입에 성공하면 원래 가려던 화면으로 자동 이동
- "익명으로 작성하기" 체크 해제 시 실제 로그인 닉네임으로 글쓴이 표시
- **공감(좋아요) 중복 방지**: 로그인 없이도 가볍게 누를 수 있는 공감이지만, 신고와 같은 방식(로그인했으면 계정, 아니면 브라우저 세션 기준)으로 한 글에 한 번만 보낼 수 있어요. 이미 보낸 글은 버튼이 "공감 보냄"으로 바뀌고 색이 채워지며 다시 눌러지지 않고, 화면을 나갔다 들어와도 그 상태가 그대로 유지돼요.
- **이미지 업로드**: 글쓰기 화면에서 사진을 최대 5장(각 5MB 이하, jpg/png/webp)까지 첨부할 수 있고, 글 상세 화면 본문 아래에 그대로 보여요. 마이페이지에서 프로필 사진도 등록할 수 있고, 등록하면 내가 쓴 글·댓글의 작성자 표시 옆에 항상 최신 프로필 사진이 함께 나와요. 다만 "익명으로 작성하기"로 남긴 글·댓글에는 작성자를 특정할 수 없어야 하므로 프로필 사진을 보여주지 않아요. 이미지는 서버가 아니라 [Cloudinary](https://cloudinary.com)에 저장되기 때문에, 서버를 재배포해도 이미지는 사라지지 않아요.
- **이메일 인증**: 이메일로 회원가입하면 인증 메일이 발송되고, 인증 여부는 계정 정보(`emailVerified`)에 남아요. 다만 인증하지 않아도 글쓰기·댓글에는 아무 제약이 없어요 — 가입 직후 바로 편하게 쓸 수 있게 하려고 일부러 막지 않았어요. 카카오/구글로 가입한 계정은 이미 검증된 이메일이라 처음부터 인증된 것으로 처리돼요.
- **비밀번호 찾기**: 로그인 화면의 "찾기" 링크로 가입한 이메일을 입력하면 재설정 링크를 보내드려요. 링크는 1시간 동안만 유효하고, 한 번 쓰면 바로 무효화돼요. 계정이 없는 이메일이어도 같은 안내 메시지를 보여줘서 가입 여부가 새어나가지 않게 했어요.
- **마이페이지**: 헤더의 "마이페이지"를 누르면 내가 쓴 글(게시판 구분 포함), 내가 쓴 댓글(어느 글에 달았는지 포함), 제재 이력(현재 정지·제한 상태, 누적 삭제 처리 횟수)을 탭으로 나눠서 볼 수 있어요. 목록의 글·댓글을 누르면 해당 글 상세 화면으로 바로 이동해요.
- **5개 게시판이 전부 실제로 동작해요**: 오늘 하루 끄적끄적 / 내가 만든 취미 자랑 / 책 한 소절, 명대사 / 나에게 스스로 위로하는 말 / 누군가에게 위로를 건네고 싶은 말. 각 게시판의 글쓰기·댓글·공감이 서버에 실제로 저장돼요. **새로고침하거나 서버를 껐다 켜도 사라지지 않아요.**
- **게시판 자체를 운영자 화면에서 추가·이름 변경·순서 변경·숨김·삭제할 수 있어요** (코드 수정 불필요). 홈 화면 카드, 카테고리 탭, 사이드바, 글쓰기 화면의 게시판 선택 목록이 전부 이 데이터를 그대로 따라가요.
- 글쓰기 화면에서 게시판을 직접 선택할 수 있어요. 기본값은 지금 보고 있던 게시판으로 자동 선택돼요.
- **본인 글·댓글 수정/삭제**: 글 상세 화면에서 본인이 쓴 글에는 "수정"/"삭제" 버튼이, 본인이 쓴 댓글에는 "수정"/"삭제" 링크가 붙어요. 수정은 제목·내용만 그 자리에서 바로 고칠 수 있고, 삭제는 확인 후 완전히 지워져요(운영자의 신고 처리와 별개). 익명으로 쓴 글도 작성자 본인에게는 계속 수정·삭제 버튼이 보여요 — 화면에 "익명"으로 표시될 뿐 서버는 실제 작성자를 알고 있거든요. 다만 로그인하지 않고 남긴 완전 익명 댓글은 애초에 작성자를 특정할 수 없어서 본인 확인이 불가능해 수정·삭제 대상이 아니에요.
- 브라우저 뒤로가기를 눌러도 사이트 밖으로 나가지 않고, 화면 안에서 이전 화면으로 돌아가요
- **페이지네이션**: 게시판 글이 10개를 넘으면 하단에 페이지 번호가 나타나요. 페이지를 넘겨도 서버에 다시 요청하지 않고 이미 받아온 목록에서 잘라 보여줘서 빠르게 넘어가요. 글이 10개 이하인 게시판은 페이지 번호 자체가 안 보여요.
- **검색**: 홈 화면 검색창은 숨김 처리되지 않은 전체 게시판을 대상으로 글 제목·내용을 검색해서, 검색 결과 화면에 어느 게시판 글인지 배지와 함께 보여줘요. 게시판 화면 안의 검색창은 지금 보고 있는 게시판 안에서만(제목 기준) 빠르게 걸러줘요 — 이미 받아온 목록에서 걸러내는 거라 서버에 다시 묻지 않아요. 검색어를 지우면 원래 목록(페이지네이션 포함)으로 바로 돌아가요.
- **금칙어 자동 필터**: 글·댓글 등록 시 욕설/비속어가 포함되어 있으면 서버가 거부해요. 공백·특수문자·초성으로 우회한 표기("시 발", "ㅅㅂ" 등)도 잡아내요. 목록은 `data/bannedWords.json`에 저장되고, 운영자 화면("운영자" → "운영자 · 금칙어 관리")에서 코드 수정 없이 바로 추가·삭제할 수 있어요.
- **신고 기능**: 글/댓글마다 🚨 신고 버튼이 있고, 사유(욕설/비방, 광고, 신상 노출, 자해 조장, 기타)를 골라 신고할 수 있어요. 같은 사람이 같은 글을 두 번 신고하는 건 막아요.
- **신고 누적 자동 숨김**: 신고가 3건 쌓이면 다른 사용자에게는 자동으로 숨겨지고, 작성자 본인에게만 "검토중" 표시와 함께 계속 보여요.
- **운영자 검수 화면**: `ADMIN_EMAILS`에 등록된 계정으로 로그인하면 상단에 "운영자" 메뉴가 생겨요. 신고된 글/댓글을 모아 보여주고, 신상 노출·자해 조장 신고는 맨 위로 올라와요. 복구/삭제(경고 누적)/삭제(중대·즉시 영구정지) 중 하나로 처리할 수 있어요.
- **운영자 · 회원 관리**: 전체 회원을 이메일·닉네임으로 검색하고, 신고가 쌓이길 기다리지 않고 바로 기간을 정해 제한하거나 영구정지할 수 있어요. 제재된 계정은 목록에서 상태(제한중/영구정지)가 바로 보이고, 언제든 "제재 해제" 버튼으로 풀어줄 수 있어요. 운영자 계정은 제재 대상에서 빠져요.
- **운영자 · 게시글 관리**: 신고 여부와 상관없이 전체 게시글을 제목으로 검색해서 바로 삭제할 수 있어요. 신고를 거치지 않는 삭제라 작성자의 제재 사다리(경고 누적)에는 영향을 주지 않아요 — 명백한 스팸·광고글을 신고가 쌓이기 전에 바로 지우고 싶을 때 써요.
- **신고 처리 SLA 알림**: 신고가 접수된 지 24시간이 지나도 운영자가 처리(복구/삭제)하지 않으면, 서버가 1시간마다 검사해서 `ADMIN_EMAILS`의 운영자 전체에게 이메일로 알려줘요. 같은 신고에는 한 번만 보내고(스팸 방지), 운영자가 처리하면 다음에 다시 신고돼도 새 SLA로 인식해요.
- **제재 사다리**: 삭제 처리가 쌓이면 3회째 7일 글쓰기·댓글 제한, 5회째(또는 신상 노출·자해 조장 등 중대 위반 1회) 영구 정지로 자동 적용돼요. 제한/정지된 계정은 글쓰기·댓글이 서버에서 막혀요 (정지 계정은 로그인 자체도 막힘).
- **모바일 화면 대응**: 화면 폭 768px 이하(휴대폰, 좁은 태블릿)에서는 게시판 화면의 사이드바·우측 위젯이 숨겨지고 본문이 전체 폭을 차지해요. 홈 화면 카드는 1열로, 글 목록 테이블은 필요하면 가로로 스크롤돼요. 신고·삭제 같은 버튼류는 터치하기 편하게 여백을 넉넉히 뒀어요. (768px보다 넓으면 지금까지처럼 3단 레이아웃 그대로예요.)

## 직접 테스트해서 확인한 것

**이메일 로그인 + 화면 흐름** (Playwright로 브라우저 자동화, 16개 시나리오 전부 통과): 비로그인 글쓰기 차단 → 로그인 화면 이동, 회원가입 후 원래 화면 복귀, 실명(닉네임) 글쓰기 반영, 로그아웃 시 세션 실제 삭제, 틀린 비밀번호 거부, 소셜 로그인 버튼 링크 확인.

**브라우저 뒤로가기** (9개 시나리오 전부 통과): 화면 이동할 때마다 브라우저 기록에 남아서, 뒤로가기를 눌러도 사이트 밖으로 안 나가고 이전 화면으로 돌아오는지 확인.

**게시글·댓글·공감 저장** (8개 시나리오 전부 통과): 글쓰기 → 새로고침해도 목록에 남아있는지, 댓글·공감이 새로고침 후에도 유지되는지, 서버를 완전히 껐다 켜도(재시작) 데이터가 남아있는지까지 확인.

**금칙어 필터·신고·운영자 검수** (16개 시나리오 전부 통과, Playwright + curl): 욕설/우회 표기 포함 글쓰기·댓글 거부, 정상 글은 정상 등록, 서로 다른 3명이 신고하면 3건째에 자동 숨김, 같은 사람 중복 신고 거부, 숨김 글은 비로그인 사용자 목록/상세에서 아예 안 보이고 작성자 본인에게만 "검토중"으로 보임, `ADMIN_EMAILS` 계정에만 "운영자" 메뉴 노출, 운영자 화면에 신고 내역·사유가 정확히 표시, 자해 조장/신상 노출 신고는 우선순위로 정렬, 복구 처리 시 다시 모두에게 공개, 삭제(경고 누적) 3회째 7일 제한 적용, 삭제(중대) 시 즉시 영구정지 및 이후 로그인 차단까지 확인.

**5개 게시판 분리 동작** (26개 시나리오 전부 통과): 홈 카드로 각 게시판 진입 시 제목·탭 활성화 표시가 맞는지, 게시판마다 시드 글이 제대로 보이는지, 글쓰기 화면의 게시판 선택이 지금 보고 있던 게시판으로 기본 설정되는지, 다른 게시판을 선택해서 쓴 글이 그 게시판에만 등록되고 다른 게시판 목록에는 안 섞이는지, 상세 화면 게시판 라벨과 "목록으로" 복귀가 글이 속한 게시판을 정확히 따라가는지, 사이드바로도 이동이 되는지, 홈/탭/사이드바 항목 수가 실제 게시판 수와 정확히 일치하는지(하드코딩된 항목이 남아있지 않은지)까지 확인.

**운영자 게시판 관리** (14개 시나리오 전부 통과): 새 게시판 생성 후 새로고침 없이 홈 화면·글쓰기 선택 목록에 즉시 반영되는지, 이름 변경이 모든 화면에 바로 반영되는지, 숨김 처리 시 운영자에게는 계속 보이되 홈 화면·비로그인 사용자에게는 사라지는지, 다시 표시 처리가 정상 동작하는지, 게시글이 있는 게시판은 삭제가 거부되고 없는 게시판만 삭제되는지, 같은 카테고리 안에서 순서(▲▼)가 정확히 바뀌는지(curl로 별도 검증)까지 확인.

**운영자 금칙어 관리 화면** (curl + 브라우저로 검증): 운영자 화면에서 단어 추가 시 목록에 즉시 반영되고 입력창이 비워지는지, × 버튼으로 삭제하면 목록에서 바로 사라지는지, 화면에서 추가한 단어가 실제 글쓰기 필터에도 즉시 반영되어 해당 단어가 포함된 글이 거부되는지까지 확인.

**신고 처리 SLA 알림** (curl로 시간을 앞당겨 검증): 신고 시각을 25시간 전으로 조작한 뒤 서버를 재시작해서 SLA 초과가 감지되고 슬라 알림 메일이 발송되는지, 발송 후 같은 신고로는 서버를 다시 켜도 재발송되지 않는지(slaNotified 플래그), 운영자가 복구 처리하면 플래그가 초기화되어 이후 재신고 시 새 SLA로 다시 인식되는지까지 확인.

**모바일 화면 대응** (브라우저로 375px·1280px 폭 비교 검증): 375px(휴대폰 폭)에서 텍스트가 확대 없이 읽히는지, 홈 카드가 1열로 쌓이는지, 게시판 화면에서 사이드바·우측 위젯이 사라지고 본문이 전체 폭을 쓰는지, 글 목록 테이블이 화면 밖으로 뚫고 나가지 않고 가로 스크롤로 처리되는지, 카테고리 드롭다운이 안 잘리고 정상적으로 열리는지, 로그인·글쓰기·마이페이지·운영자 화면까지 전부 확인. 1280px(데스크톱 폭)에서는 기존 3단 레이아웃이 그대로 유지되는지도 함께 확인.

**본인 글·댓글 수정/삭제** (curl + 브라우저로 검증): 본인 글/댓글은 수정·삭제가 되고 다른 사람 글/댓글은 403으로 거부되는지, 로그인하지 않고 남긴 완전 익명 댓글은 본인 확인이 불가능해 수정·삭제 대상에서 자연히 제외되는지, 화면에서 수정하면 그 자리에서 바로 반영되고 삭제하면 목록으로 돌아가는지, 댓글 수정·삭제·재조회 시 조회수가 중복으로 올라가지 않는지까지 확인.

**페이지네이션** (curl로 글 15개까지 늘려 브라우저로 검증): 글이 10개를 넘는 게시판에서 1페이지에 최신 10개, 2페이지에 나머지가 정확히 나뉘어 나오는지, 페이지 번호를 누르면 서버 재요청 없이 즉시 전환되는지, 다른 게시판으로 이동하면 페이지가 1로 리셋되는지, 글이 10개 이하인 게시판은 페이지 번호가 아예 안 보이는지까지 확인.

**검색** (curl + 브라우저로 검증): 제목에만 있는 단어와 본문에만 있는 단어 둘 다 전체 검색에서 찾아지는지, 새로 쓴 글이 바로 검색되는지, 검색 결과 화면에 게시판 배지가 정확히 붙고 클릭 시 글 상세로 이동하는지, 결과가 없을 때 안내 문구가 뜨는지, 게시판 안 검색이 서버 재요청 없이 그 게시판 글만 걸러내는지, 검색어를 지우면 전체 목록과 페이지네이션이 그대로 복원되는지, 다른 게시판으로 이동하면 검색창이 비워지는지까지 확인.

**공감 중복 방지** (curl + 브라우저로 검증): 처음 공감은 성공하고 같은 세션으로 다시 누르면 409로 거부되는지, 다른 방문자(다른 세션)는 같은 글에 정상적으로 공감할 수 있는지, 로그인 계정은 브라우저 세션이 달라져도(로그아웃 후 재로그인) 계정 기준으로 계속 막히는지, 화면에서 버튼이 "공감 보냄"으로 바뀌고 다시 눌러도 서버에 요청조차 안 가는지, 글을 나갔다 다시 열어도 공감 상태가 서버 기준으로 정확히 복원되는지까지 확인.

**요청 제한(rate limiting)** (curl로 연속 요청해서 검증): 회원가입을 연속 6회 시도하면 5회까지만 성공하고 6번째부터 429로 막히는지, 로그인을 11회 연속 실패시키면 10회까지는 401(정상 실패)이고 11번째부터 429로 바뀌는지, 비밀번호 찾기도 6회째부터 막히는지, 글 목록 조회 같은 다른 API는 이 제한과 무관하게 계속 정상 동작하는지까지 확인.

**이미지 업로드** (curl + 브라우저로 검증): 프로필 사진 1장과 글쓰기 사진 여러 장이 실제로 Cloudinary에 올라가고 URL이 정확히 반환되는지, 텍스트 파일처럼 잘못된 형식은 거부되는지, 6장을 한꺼번에 올리면 5장 제한에 걸리는지, 로그인하지 않은 상태의 업로드 시도가 차단되는지, 신뢰할 수 없는 외부 URL을 글에 끼워 넣으려 하면 서버가 걸러내는지(Cloudinary 도메인이 아닌 URL은 저장되지 않음)까지 확인. 브라우저로는 파일 선택 → 미리보기 썸네일 → 등록까지의 전체 흐름과, 글 상세·댓글에 작성자 프로필 사진이 표시되되 익명 글·댓글에는 표시되지 않는 것까지 확인.

**운영자 회원·게시글 관리** (curl + 브라우저로 검증): 전체 회원·게시글 목록과 검색이 정확히 동작하는지, 기간 제한을 걸면 실제로 그 날짜까지 글쓰기·댓글이 막히는지, 제재 해제 후 다시 쓸 수 있게 되는지, 영구정지된 계정은 로그인 자체가 막히는지, 운영자 계정은 제재 시도 자체가 거부되는지, 신고 없이 게시글을 바로 삭제할 수 있는지까지 확인. 브라우저에서 버튼 클릭으로 제한·해제·삭제가 화면에 즉시 반영되는 것도 확인.

**카카오/구글 로그인**: 실제 카카오·구글 서버 대신 흉내낸 테스트 서버로 전체 흐름(인가 화면 리다이렉트 → 토큰 교환 → 프로필 조회 → 계정 생성/연결 → 세션 발급)을 curl로 검증했어요.
- 카카오 최초 로그인 → 새 계정 생성, 재로그인 → 같은 계정으로 인식(중복 생성 안 됨)
- 구글 로그인 → 별도 계정으로 정상 생성
- 이메일이 같은 기존 이메일 가입 계정에 카카오 로그인 → 새 계정을 만들지 않고 기존 계정에 연결, 기존 비밀번호 로그인도 계속 가능
- API 키가 설정되지 않은 상태로 카카오/구글 버튼을 누르면 설정 안내 화면이 뜨는 것도 확인

(실제 카카오/구글 계정으로 로그인 버튼을 눌러보는 최종 확인은 `.env`에 발급받은 키를 넣은 뒤 직접 해보셔야 해요 — 이 키는 cho님 명의로만 발급받을 수 있어서 저는 대신 발급받아드릴 수 없어요.)

**이메일 인증 · 비밀번호 찾기** (curl로 전체 흐름 검증): 회원가입 직후 인증 메일이 발송되는지, 인증 링크로 인증 완료 처리가 되고 같은 링크를 다시 열면 "유효하지 않은 링크"로 막히는지, 비밀번호 찾기 요청 시 가입 여부와 무관하게 항상 같은 안내 메시지가 오는지(계정 존재 비노출), 재설정 링크로 비밀번호를 바꾸면 새 비밀번호로는 로그인되고 옛 비밀번호는 거부되는지, 사용한 재설정 링크를 다시 쓰면 막히는지까지 확인. (Gmail 앱 비밀번호를 아직 설정하지 않아서, 실제 발송 대신 서버 콘솔에 출력된 링크로 검증했어요 — `.env`에 `GMAIL_USER`/`GMAIL_APP_PASSWORD`를 채우면 실제 메일함으로도 확인해보실 수 있어요.)
- 이후 미인증 상태에서도 글쓰기·댓글이 막히지 않도록 바꾸면서, 헤더의 인증 안내 문구와 인증 메일 재발송 기능(화면·API)은 함께 정리했어요. 미인증 상태로 글쓰기·댓글이 정상적으로 되는지, 제거한 `/api/resend-verification`이 실제로 404가 되는지 curl과 브라우저로 재확인했습니다.

## 데이터는 어디에 저장되나요

`data/users.json`(회원, 신고 누적·제재 상태 포함), `data/posts.json`(게시글·댓글, 신고 내역·숨김 상태 포함), `data/boards.json`(게시판 목록), `data/bannedWords.json`(금칙어 목록)에 저장돼요 (검증 단계용 가벼운 방식). 실 서비스로 나갈 때는 PostgreSQL/MySQL 같은 실제 데이터베이스로 옮기는 걸 추천해요.

## 보안 관련 참고

- `server.js`의 `SESSION_SECRET`은 데모용 기본값이에요. 실제로 배포할 때는 반드시 `.env`에 별도의 랜덤한 값을 지정해주세요. (로컬 `.env`는 이미 랜덤 값으로 채워뒀어요 — 배포 서버에는 별도로 새 값을 지정해주세요.)
- `.env` 파일은 절대 깃허브 같은 공개 저장소에 올리지 마세요 (`.gitignore`에 이미 포함되어 있어요).
- **로그인·회원가입·비밀번호 찾기에 요청 제한(rate limiting)이 걸려 있어요**: 같은 IP에서 로그인은 15분에 10회, 회원가입·비밀번호 찾기는 1시간에 5회를 넘으면 잠시 막혀요. 무차별 대입으로 비밀번호를 맞추거나 봇으로 계정을 대량 생성하는 걸 막기 위한 거예요. 글쓰기·댓글 등 다른 API는 이 제한과 무관해요. **개발 중(로컬)에는 이 제한이 걸리지 않아요** — `NODE_ENV=production`으로 실행했을 때만 실제로 적용돼요. 배포할 때는 반드시 `NODE_ENV=production`으로 실행해주세요.
